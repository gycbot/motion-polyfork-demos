## When the owner corrects something (fix A, also find B, C, D)
1. **Restore the real goal**: treat the owner's example as a sample, not the full list.
2. **Root cause**, then sweep: B = misses in the same task; C = the same class in other templates / roles / platforms / skills; D = dependencies, side effects and things the owner has not mentioned yet.
3. **Fix in the same job** what is necessary and reversible; for cross-role items the captain names one owner. Generalizing is not a license to widen scope, raise cost, edit standing originals, touch accounts or get publish approval.
4. **Log one row the same day** in the existing T2530 ledger (no second ledger): `quote/goal | root cause | sibling scope & exceptions | single entry fixed + path/MD5, or why not | owner | next natural task check & proof | status`.
5. **Put it in the right place**: shared methods go into entry skills (`skill-first-task`, this skill); a lock for one shot/character/platform goes into that specialist skill or asset card. Do not turn a local note into a team-wide ban.
6. **Prove it on the next natural task**: cite the row and show real evidence there. Status stays "changed, awaiting use" until then; an ACK or an edited file is not proof, and do not render filler just to close it.
7. Update durable memory with the generalized preference.
